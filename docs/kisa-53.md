# KISA 보안 기능 53개 성숙도 자가 진단 (2026-11-14)

기준: 과기정통부·KISA 「에이전틱 AI 제로트러스트 안내서」(2026-11) 3장.

- 보안 기능 53개 목록: 표 3-4
- 기능별 성숙도 기준(기존·초기·향상·최적화): 표 3-13 ~ 3-65

안내서는 "모든 기능을 최적화까지"가 아니라 핵심 위험 영역부터 높이라고 권한다(3장 3절). 이 표도 그렇게 읽는다.

## 매기는 방법

- **단계는 그 단계의 정의를 대부분 채울 때만 준다.** 일부만 채우면 아래 단계를 주고 "(향상 일부)"처럼 적는다.
- **근거**는 시험, 평가 묶음([evaluation.md](evaluation.md)), 실환경 확인 중 하나가 있는 것만 쓴다.
- **범위 밖**: 이 프로젝트가 다루지 않는 영역이다. 피지컬 리소스, 모델 학습 데이터, 사용자의 원격 접속 방식이 여기에 든다. 이 프로젝트의 범위는 사내 코딩 에이전트의 **실행 계층**이다([fsi-17.md](fsi-17.md)).
- **이 환경 기준이다.** 직원 PC 센서, 팀 공용 게이트웨이, 중앙 MCP 게이트웨이, 관제 서버로 이루어진 데모 환경이다. 망 분리처럼 compose로만 구성한 것은 그렇게 적었다.
- 기존 가이드라인 2.0의 기능(일반 IAM, EDR, DLP 등)이 있다고 가정하지 않았다. 이 프로젝트가 직접 하는 것만 센다.

읽는 법:

- **가장 깊은 곳은 행위 통제다(P4·P5).** 모든 툴 호출을 실행 전에 같은 서명된 룰로 판정하고, 가역성 등급으로 승인 방식을 정한다. 안내서 주안점 1(접근 통제에서 행위 통제로)과 같은 방향이다.
- **최적화가 하나도 없는 이유는 공통이다.** 최적화 단계는 대부분 실시간 신뢰 점수, AI 기반 판단, 완전 자동 대응을 요구한다. 이 프로젝트는 신뢰 점수 대신 규칙 기반 위험도(사람·PC 상태)를 쓴다. 판정에 LLM을 쓰지 않는 것은 의도한 결정이다. 안내서 각주 8이 말하듯 판정기 자체가 인젝션 대상이 되기 때문이다([zero-trust.md](zero-trust.md#작업-범위-프로필-의도-검증에-대한-입장)).
- **기존(4개) 중 두 개는 일부러 안 한 것이다.** C2-5(AI 기반 판단)는 위 결정 때문이다. P1-2(연합 신원)는 사람 단위 인증(SSO)을 범위 밖으로 둔 결정 때문이다. 나머지 두 개(P6-4 암호화, C1-5 위협 인텔리전스)는 손대지 않은 빈 곳이다.
- **"향상"이어도 패턴 판정의 한계는 남는다.** 값이나 문구를 바꾸면 놓친다(평가의 우회 E01~E07). 해당 기능 행에 적었다.

| P1-5 | 접근 관리 및 위임권한 통제 | 향상 | 세션 단위가 아니라 툴 호출마다 판정한다. 위임 트리(부모·뿌리 대화, 깊이)를 기록한다. 하위 에이전트가 부모보다 큰 권한을 받으면 사용자 승인으로 넘긴다(Claude Code 정의, OpenClaw `sessions_spawn`, [delegation-permissions.md](delegation-permissions.md)). 팀별 작업 범위 프로필이 있다 | 권한을 강제로 줄이지 않고 묻는다. 하위 에이전트 실행 한도의 합계(권한 총량) 검증과 JIT 권한이 없다 |

## P3 네트워크

| ID | 보안 기능 | 수준 | 근거 | 다음 단계에 빠진 것 |
|---|---|---|---|---|
| P3-1 | 네트워크 세분화 | 초기 (향상 일부) | 팀 게이트웨이의 에이전트 망을 격리하고 egress 프록시로만 내보낸다. 사내 CRM은 중앙 MCP 게이트웨이와만 같은 망(`crm-net`)에 있다. 다른 PC에서 직접 연결하면 실패한다(실환경). 모두 compose로 구성했다 | 에이전트 신원·신뢰 수준별 세그먼트 정책. 직원 PC의 Claude Code 경로는 망으로 격리하지 않는다 |
| P3-2 | 위협 대응 | 초기 (향상 일부) | 미허가 외부 호스트 차단(`egress-unapproved-host`). 비인가 데이터 전송 차단(민감 파일, 비밀값, 보호 데이터). 여러 사람에게 같은 지표가 나오면 캠페인으로 묶는다 | 에이전트별 정상 통신 프로파일과 이탈 탐지. 위협 인텔리전스 연계 |
| P3-3 | 에이전트 통신 보안 | 초기 (향상 일부) | 장비→LAN 게이트웨이 mTLS. MCP는 등록된 서버만 쓰고, 툴 설명이 바뀌면 그 툴을 숨기고 호출을 거부한다(`mcp-tool-description-poisoning`, 평가 A13) | A2A 상호 인증, 프로토콜 버전·스키마 검증, 메시지 서명·재전송 방지. 에이전트 간 채널은 각 제품에 맡긴다 |
| P3-4 | 트래픽 관리 | 초기 | egress 프록시가 게이트웨이별 외부 목적지를 기록한다. 툴 호출 빈도를 제한한다(`rate-limit-tool-calls`) | 에이전트 식별자 기반 트래픽 분리와 통계, 비정상 트래픽 자동 제한 |
| P3-5 | 외부 연결 통제 | 향상 | 서명된 정책의 허용 도메인으로 egress를 처음부터 차단 모드로 둔다(텔레메트리·날씨 호스트 차단, 실환경). 미허가 MCP 서버 URL을 탐지한다(`unapproved-mcp-server-url`). 명령·인자에서 파싱한 목적지도 판정한다 | 직원 PC 경로는 네트워크 경계가 아니라 명령 판정만 한다. 신뢰 점수·위협 인텔리전스 기반 동적 검증 |
| P3-6 | 네트워크 회복성 | 초기 | 관제 서버와 끊기면 fail closed로 처리한다([fail-closed.md](fail-closed.md): 서명된 정책 캐시, 낡은 정책은 읽기 전용만). 전송 대기열에 우선순위가 있다. 센서 상태 신호(`sensor.health`)를 보낸다 | 이중화·장애 조치·대체 경로 |

## P4 시스템

| ID | 보안 기능 | 수준 | 근거 | 다음 단계에 빠진 것 |
|---|---|---|---|---|
| P4-1 | 에이전트 자율 실행 통제 | 향상 | 셸·파일·네트워크·MCP 호출을 실행 전에 판정한다(Claude Code hook, OpenClaw 플러그인, MCP 게이트웨이). PC 상태·사람 위험도·작업 범위에 따라 제한한다. 인젝션 뒤 행동은 차단한다. 우회 실행을 탐지한다. 평가 공격 15종이 설계대로 처리됐다 | 신뢰 점수에 따른 동적 조정. 불필요한 권한의 자동 회수 |
| P4-2 | 가역성·실시간성 기반 행위 통제 | 향상 | 행동 룰마다 `grade:` 태그가 있다. 등급과 응답이 어긋나면 시험이 잡는다. 승인 원칙(2026-11-14): 3-1은 사용자 승인 + 보안팀 사후 검토 큐, 외부 유출과 공격 진행 신호는 바로 차단([zero-trust.md](zero-trust.md#승인-원칙-2026-11-14)) | 3-2(실시간 비가역) 사전 승인 정책. 해당하는 행동이 없어 쓰지 않는다 |
| P4-3 | 피지컬 리소스 접근 통제 | 범위 밖 | - | - |
| P4-4 | 시스템 계정 관리 | 초기 | 관제 서버의 관리 토큰과 읽기 전용 대시보드 토큰을 나눴다. 팀 게이트웨이는 공유 계정 대신 직원별 신원 프록시와 보안팀 역할을 쓴다. 장비 토큰을 폐기할 수 있다 | PAM, JIT 임시 권한, 장기 미사용 계정 탐지 |
| P4-5 | 네트워크 분리 정책 | 초기 (향상 일부) | 에이전트 실행 구역, 데이터 구역(`crm-net`), 외부(`internet-sim`)를 나눴다. 데이터 구역으로 가는 길은 mTLS LAN 게이트웨이 → 중앙 게이트웨이(비밀값)뿐이다(실환경 403 확인) | compose 데모 구성이다. 신뢰 수준에 따른 동적 조정 |
| P4-6 | 시스템 보안 및 정책 관리 | 향상 | 정책은 Ed25519로 서명해 중앙에서 배포하고, 센서가 주기적으로 받는다. 공통·팀 계층이 있고 변경 이력이 남는다. 정책 유효기간이 있다. 설정 변경과 무결성 훼손을 자동 탐지하고, 변조된 플러그인·스킬은 격리한다 | 시스템 전반의 실시간 신뢰도 평가와 자동 권한 축소 |

## 안내서 4장 시나리오와의 대응

안내서 3절의 5개 시나리오를 이 프로젝트로 막을 수 있는지 본다. 재현 근거는 평가 묶음([evaluation-results.md](evaluation-results.md))과 실환경 확인이다.

| 시나리오 | 이 프로젝트의 대응 | 재현 | 판단 |
|---|---|---|---|
| 1. 인젝션을 통한 목표 탈취(메일로 내부 데이터 외부 전송) | 입력 PEP가 인젝션 결과를 가림(A14). 인젝션 뒤 민감 행동 차단(A05). 외부 전송 차단(A03·A08·A15, egress). 작업 목적과 행위의 불일치는 작업 범위 프로필로 확인 | 평가 A05·A14·A08·A15 | 대응. 단, 문구를 바꾼 인젝션은 놓친다(E03) |
| 2. AI 생성 코드를 통한 RCE | 파괴적 명령과 받은 파일 실행·`curl \| sh`는 사용자 승인(A01·A09·A10). 외부 연결은 egress 허용 목록 | 평가 A01·A09·A10 | 부분. 생성 코드 정적 분석과 샌드박스 격리가 없다. 스크립트 안의 삭제는 놓친다(E02) |
| 3. 보상 해킹 에이전트의 대량 삭제 | 클라우드·DB 삭제 명령은 3-1 등급으로 사용자 승인(`destructive-cloud-command`, `destructive-sql`, A02). 승인한 뒤에는 보안팀 사후 검토. 원격 킬 스위치·격리 | 평가 A02, 원격 대응 실환경 | 부분. 행동 기준선 이탈 탐지가 없어, 보상 해킹 자체를 판정하지 못한다 |
| 4. 승인 피로를 이용한 신뢰 악용 | 승인 피로 지표(5초 안 승인, 반복 요청, 자동화 후보). 외부 유출은 사용자 승인 없이 바로 차단하므로 승인 흐름에 섞이지 않는다 | 콘솔 승인 피로 패널 | 부분. 고위험 요청을 별도 승인 채널로 보내지 않는다. 피로 패턴 자동 탐지 없음 |
| 5. MCP 공급망 침해(postmark-mcp) | 등록된 MCP 서버만 쓴다(미승인 서버 격리). 툴 설명 변조 숨김(A13). 자격증명은 중앙 게이트웨이 보관 | 평가 A13 | 부분. 허가된 서버가 나중에 악성화되는 것(숨은 참조 추가)은 못 막는다. SBOM 의존성 추적이 없다 |
