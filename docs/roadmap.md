# 로드맵

각 마일스톤은 1~2개 작업 세션 분량이고, 끝나면 **데모 가능한 상태**가 되도록 쪼갰다.

## 방향 전환 (2026-11-13)

- **중심 주제: 회사가 실제로 쓰는 AI 에이전트를 한곳에서 찾고(발견), 정하고(정책), 막고(실행 전 통제), 감사·대응한다.**
  회사에서 공식으로 쓰는 것은 코딩 에이전트(Claude Code 등), MCP로 연결한 사내 도구, 자체 제작 에이전트다. OpenClaw 같은 개인 비서형
  에이전트는 공식 도입보다 **직원이 몰래 설치하는 섀도 AI**로 나타난다. 그래서 OpenClaw 작업은 가장 깊게 통제해 본 어댑터이자
  섀도 AI 사례로 남기고, OpenClaw 전용 기능은 더 늘리지 않는다.
- **목표 직무에 맞춘 기준**: 금융보안원 security/tech. 금융보안원이 2026-10-07 발표한 「AI 모델 위협 점검 기준 및 AI 에이전트 보안 평가기준(안)」은
  레드티밍 범위를 모델 계층에서 **실행 계층**으로 넓혔다(실행 권한 및 격리 관리, 도구 실행 및 승인 통제, 작업 범위 및 결과 확인,
  자율 실행 제한 및 중단 여부). 이 프로젝트의 통제가 그 항목에 어떻게 대응하는지 평가 단계에서 표로 보인다. 금융권 망분리 개선(생성형 AI·SaaS 허용과
  보안 조건)도 배경으로 쓴다.
- **남은 기간 약 1주 (2026-11-20까지)**: 아래 "1주 계획"만 한다. 나머지는 미룬 과제로 둔다.
- 아래의 이전 방향 항목 중 원칙(스키마 우선, 로컬 판정·중앙 정책, 서명된 정책, 팀은 더 엄격하게만, 단계적 판정 등)은 그대로 유효하다.

## 이전 방향 (2026-11-10 확정, 2026-11-11 갱신)

- **(2026-11-13 전환 전) 중심 주제: 사내 OpenClaw 안전 운영** (2026-11-11). 먼저 OpenClaw 하나를 회사에서 안전하게 쓰는 데 필요한 것을 깊게 만들고,
  Claude Code·MCP·LangGraph·Gemini·Codex는 그 위에 확장한다. 공통 스키마와 센서 구조는 그대로라 나중에 붙이기 쉽다.
- **공식 사용 경로는 회사가 운영하는 팀 공용 게이트웨이**다. 에이전트는 서버의 격리된 작업 공간에서만 실행되고, 통제 장치·자격 증명·외부 통신이
  한곳에 모인다. 직원 노트북의 개인 설치는 막는 대상이 아니라 **탐지·관리 대상**이다(설치 여부, 회사 기준선 준수 여부).
- **WS 어댑터는 관측·탐지, 차단은 플러그인** (2026-11-11, 결정 B): v4 게이트웨이는 다른 사람의 실행 중단과 승인 요청 열람을 `operator.admin`에게만 허락한다.
  센서에 admin을 주지 않고, 실행 전 차단은 게이트웨이 안에서 도는 M5c 플러그인이 맡는다.
- **팀 게이트웨이의 사람 단위 기록과 최소 권한** (2026-11-12): 직원끼리는 대화를 볼 수 없고(`sessions.others: none`) 보안팀 역할만 전체를 본다.
  대화 원문은 룰에 걸린 것만 중앙에 보낸다. OpenClaw가 승인자를 기록하지 않아 소스를 고치는 대신 신원 프록시 뒤에 감사 프록시를 둔다.
- **OpenClaw 하네스는 두 겹**이다. 게이트웨이 플러그인(`before_tool_call`)이 모든 툴을 실행 전에 판정하고, WebSocket 어댑터가 독립적으로
  모든 실행을 관측한다. 플러그인이 꺼져도 어댑터에는 보이므로, 판정 기록 없는 실행을 우회로 탐지한다.

- **목적**: 취업 면접용 포트폴리오. 팀 프로젝트(SG)를 다시 이해하고 한 단계 발전시키는 것이 출발점이다.
- **넓이보다 깊이**: 에이전트 종류를 늘리기보다 차단·정책·상관 분석을 깊게 한다. Gemini CLI·Codex CLI는 선택 과제로 내렸다.
- **SG 연결 유지**: OpenClaw 어댑터는 앞쪽에 두고 SG 코드를 최대한 재사용한다. 무엇을 왜 바꿨는지 문서로 남긴다.
- **센서는 단순하게, 콘솔은 공들여**: 센서는 UI 없는 CLI/데몬으로, 설치는 한 줄로 한다. 콘솔은 별도 웹 앱으로 만든다.
- **콘솔 스택**: React + Vite + TypeScript로 새 앱을 만들고, SG `security-viz`에서 쓸 만한 컴포넌트만 가져온다.
- **저장소**: SQLAlchemy로 추상화하고 SQLite로 시작한다. 동시 쓰기 병목이 실제로 생기면(M10·M12 예상) Postgres로 바꾸고, 그때는 접속 URL만 교체한다.
  마이그레이션 도구(Alembic)는 스키마가 자주 바뀌는 M9에서 도입하고, 그 전에는 테이블을 바로 생성한다.
- **정책 서명**: 서버가 Ed25519로 정책 묶음에 서명하고 센서가 검증한다. 전송 중 위조와 엔드포인트의 캐시 파일 변조를 함께 막는다.
  센서는 기본으로 등록 응답에서 서버 공개키를 받아 저장하고(처음 한 번 신뢰), 선택으로 설치 시 공개키를 직접 지정(고정)할 수 있다.
- **장비 신원**: M3~M11은 장비 토큰으로 인증한다. 다른 PC가 네트워크로 붙는 M12에서 장비 인증서(mTLS)를 더한다.
  인증서를 써도 이벤트 안의 `device_id` 검사는 그대로 유지한다.
- **로컬 데몬**: 엔드포인트마다 `sga-sensor run` 데몬이 상주하며 룰 엔진 상태(시퀀스·빈도)를 들고 있다.
  OpenClaw처럼 오래 붙어 있는 어댑터는 데몬 안에서 돌고, Claude Code hook처럼 호출마다 뜨는 어댑터는 로컬 소켓으로 판정만 묻는다.
- **판정할 수 없을 때는 단계적으로 줄인다** (처음 정한 fail-open에서 변경):
  데몬이 없으면 hook이 서명된 정책 캐시를 직접 읽어 상태가 필요 없는 룰(패턴·허용 목록)만으로 판정한다.
  캐시도 없으면 읽기 전용 툴은 허용하고, 셸·네트워크·쓰기는 차단하거나 승인을 받는다. 그룹별 조절은 M9.
- **정책은 공통 기준선 + 팀별 강화**: 공통 정책이 모든 장비의 최소 기준(baseline)이다. 팀(그룹) 정책은 그 위에서 **더 엄격하게만** 바꿀 수 있다
  (룰 추가·켜기, 응답 단계 상향 — 예: 데이터팀은 `destructive-sql`을 block, 허용 목록 축소). 완화는 팀 정책으로 할 수 없고,
  필요하면 보안팀이 공통 정책 자체를 고친다(M9). 그 전까지는 룰 파일의 응답 단계가 모두에게 적용된다.
- **승인은 사용자가, 감사는 보안팀이**: `require_approval`은 사용자 본인이 에이전트 화면에서 승인한다. 승인·거절 결과는 모두 기록되고,
  보안팀은 콘솔에서 "사용자가 승인한 위험 행동"을 사후 감사하다가 이상하면 원격 조치(세션 중단, 격리)를 한다(M7 감사 화면, M11 원격 대응).
- **줄어든 판정은 라벨로 남긴다**: 그렇게 처리된 이벤트에 `labels["sga_verdict"]`(예: `degraded`, `fallback`)를 붙여 기록한다. 스키마는 바꾸지 않는다.
- **전송 대기열 우선순위**: 이벤트에 등급(낮음·보통·높음·긴급)을 매긴다. 대기열이 차면 낮은 등급부터 버리고, 다시 연결되면 높은 등급부터 보낸다.
- **가상 직원 LLM**: 기본은 로컬 Ollama(외부 API 불필요)로 하고, 직원마다 모델 백엔드를 설정으로 바꿀 수 있게 한다.
  개발 머신은 Mac 16GB이므로 Ollama는 호스트에서 직접 실행하고(Docker 안에서는 Metal GPU를 못 쓴다), 7~8B급 모델 하나를 직원들이 공유한다.
  동시에 움직이는 직원은 2~3명으로 잡고, 나머지는 일과 스케줄로 순서를 나눈다.

진행 순서대로 적었다. 번호는 처음 계획에서 붙인 것이라 순서와 다를 수 있다(다른 문서가 번호로 참조한다).

| # | 마일스톤 | 완료 기준 | 상태 |
|---|---|---|---|
| M1 | 저장소 뼈대 + 공통 스키마 v1 | `AgentEvent`/`Finding` 모델, JSON Schema, 6개 센서 예시 이벤트, 테스트 | ✅ |
| M2 | 로컬 탐지 엔진 | SG `detect.py` 룰 타입 이전(regex/rate/loop/sequence/inventory diff), redaction, S1~S3 룰 통과 | ✅ |
| M3 | Control Plane API | FastAPI + SQLAlchemy(SQLite): 장비 등록(토큰), 이벤트·finding 수집, 정책 v0(`rules/` 묶음 + 해시) 조회, compose 뼈대, 위협 모델 초안(`docs/threat-model.md`) | ✅ |
| M4 | Sensor core | 어댑터 인터페이스, 정책 pull·캐시(중앙이 끊기면 마지막 정책 사용), 정책 서명(Ed25519) 검증, 전송 큐·재시도, 등록 CLI. 예시 이벤트 replay로 센서 → 중앙 엔드투엔드 | ✅ |
| M5 | 로컬 데몬 + OpenClaw 어댑터 | `sga-sensor run`(어댑터 실행, 주기적 정책 동기화·전송), SG ingest/respond 이전, 사후 abort 집행, 셸 명령은 exec 승인으로 사전 거절, SG 대비 변경점 문서(`docs/from-sg.md`). **게이트웨이 프로토콜 v4 대응**: 센서 자체 장치 신원 + 페어링 + `deviceToken`, `tool-events` 기능 선언. v4 실환경에서 관측·탐지 확인, 실행 전 차단은 M5c로 넘김(결정 B) | ✅ |
| M5b | OpenClaw 팀·다중 사용자 | **팀 공용 게이트웨이를 주 데모 환경으로**. 에이전트별 인벤토리(`tools.catalog` agentId), 세션 소유자를 사용자로 귀속(다중 사용자 모드), 하위 에이전트 위임 체인 추적(부모↔자식 세션), 에이전트 간 인젝션 전파 탐지(T18), `openclaw agents team create`로 팀 데모. 진행([team-gateway.md](team-gateway.md)): compose 팀 게이트웨이(trusted-proxy, 직원별 포트, 보안팀 역할) ✅, 툴 호출·프롬프트를 시킨 사람으로 기록 ✅, 감사 프록시로 승인·중단·대화 보관·삭제를 한 사람 기록(OpenClaw는 승인자를 앱 이름으로만 저장) ✅, 대화 공개 범위 `none`·룰에 걸린 대화만 원문 전송 ✅, Code Mode 승인 중복 제거(룰 `unless`) ✅, 하위 에이전트 위임 사슬(부모·뿌리 세션, 깊이, 위임한 사람으로 기록) ✅, 위임을 통한 인젝션 전파 탐지(T18: 위임 트리 시퀀스, 작업 지시 전달 승인) ✅ (2026-11-12 실환경 확인). 에이전트별 인벤토리(모델·런타임·권한 모드·스킬, 미허가 스킬·`full` 권한 경보, 두 번째 에이전트로 확인) ✅. 직원 역할은 OpenClaw 제약으로 하위 에이전트 불가(공개 범위 `none` 유지 결정) | ✅ |
| M5c | OpenClaw 플러그인 사전 차단 | TypeScript 플러그인의 `before_tool_call` → 로컬 소켓 → 데몬 판정. 모든 툴에 block·`requireApproval`(사용자 승인)·결과 기록. 데몬 없으면 단계적 처리 + 라벨. 어댑터가 본 실행 중 플러그인 판정이 없는 것을 우회 finding으로. 플러그인 신호 감시(`sensor.health`, 끊김 finding·복구 기록), 상시 운영(LaunchAgent). 실환경에서 OpenClaw·Codex 런타임 차단, 데몬 꺼짐 시 단계적 차단, 끊김·우회·복구 확인 | ✅ |
| M5d | 실행 격리·외부 통신·기준선 | OpenClaw 샌드박스·권한 모드·exec 정책이 회사 기준선대로인지 점검, 네트워크 프록시를 egress 프록시(허용 도메인)로 연결, 플러그인·스킬 허용 목록과 버전 변경 시 재승인, 직원 PC의 비관리 OpenClaw 설치 탐지, **모든 모델의 런타임 고정과 Codex에 묶인 세션 점검**(T19). 진행: 설정 기준선 감시(`config.snapshot`: 플러그인 상태·exec·런타임, 2026-11-11 실환경 확인) ✅, 플러그인 `bye`로 언로드 즉시 감지 ✅, 설치된 코드 무결성(npm 서명 + Sigstore 출처로 검증한 배포본 해시와 비교, 출시 3일 대기, 변조 시 격리) ✅, 스킬 무결성(보안팀이 해시로 승인, 변조 시 스킬 비활성화, 2026-11-12 실환경) ✅, 샌드박스 기준선(꺼짐 경보, 기본값 포함)과 대화 단위 권한 올리기 감사(감사 프록시) ✅, egress 프록시(에이전트 망 격리 + 서명된 정책의 허용 도메인으로 차단, chatgpt.com만 추가) ✅, 비관리 OpenClaw 설치 탐지(설치 흔적 스캔, 관리 여부·네트워크 노출 경보, `carol-pc` 데모) ✅, T19 게이트웨이가 실제로 쓰는 런타임(고정 안 된 선택 가능 모델, 예전 런타임에 묶여 남은 대화, 2026-11-12 실환경) ✅, 모델 허용 목록으로 고정한 모델만 선택 가능(A안, 허용 밖 모델의 예전 대화는 게이트웨이가 허용 모델로 바꿈) | ✅ |

| # | 마일스톤 | 완료 기준 | 상태 |
