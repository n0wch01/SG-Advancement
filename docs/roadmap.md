# 로드맵

각 마일스톤은 1~2개 작업 세션 분량이고, 끝나면 **데모 가능한 상태**가 되도록 쪼갰다.

## 방향 (2026-11-10 확정)

- **목적**: 취업 면접용 포트폴리오. 팀 프로젝트(SG)를 다시 이해하고 한 단계 발전시키는 것이 출발점이다.
- **넓이보다 깊이**: 에이전트 종류를 늘리기보다 차단·정책·상관 분석을 깊게 한다. Gemini CLI·Codex CLI는 선택 과제로 내렸다.
- **SG 연결 유지**: OpenClaw 어댑터는 앞쪽에 두고 SG 코드를 최대한 재사용한다. 무엇을 왜 바꿨는지 문서로 남긴다.
- **센서는 단순하게, 콘솔은 공들여**: 센서는 UI 없는 CLI/데몬으로, 설치는 한 줄로 한다. 콘솔은 별도 웹 앱으로 만든다.
- **콘솔 스택**: React + Vite + TypeScript로 새 앱을 만들고, SG `security-viz`에서 쓸 만한 컴포넌트만 가져온다.
- **저장소**: SQLAlchemy로 추상화하고 SQLite로 시작한다. 동시 쓰기 병목이 실제로 생기면(M10·M12 예상) Postgres로 바꾸고, 그때는 접속 URL만 교체한다.
  마이그레이션 도구(Alembic)는 스키마가 자주 바뀌는 M9에서 도입하고, 그 전에는 테이블을 바로 생성한다.
- **정책 서명**: 서버가 Ed25519로 정책 묶음에 서명하고 센서가 검증한다. 전송 중 위조와 엔드포인트의 캐시 파일 변조를 함께 막는다.
  센서는 기본으로 등록 응답에서 서버 공개키를 받아 저장하고(처음 한 번 신뢰), 선택으로 설치 시 공개키를 직접 지정(고정)할 수 있다.
- **장비 신원**: M3~M11은 장비 토큰으로 인증한다. 다른 PC가 네트워크로 붙는 M12에서 장비 인증서(mTLS)를 더한다.
  인증서를 써도 이벤트 안의 `device_id` 검사는 그대로 유지한다.
- **로컬 데몬**: 엔드포인트마다 `sentinel-sensor run` 데몬이 상주하며 룰 엔진 상태(시퀀스·빈도)를 들고 있다.
  OpenClaw처럼 오래 붙어 있는 어댑터는 데몬 안에서 돌고, Claude Code hook처럼 호출마다 뜨는 어댑터는 로컬 소켓으로 판정만 묻는다.
- **판정할 수 없을 때는 단계적으로 줄인다** (처음 정한 fail-open에서 변경):
  데몬이 없으면 hook이 서명된 정책 캐시를 직접 읽어 상태가 필요 없는 룰(패턴·허용 목록)만으로 판정한다.
  캐시도 없으면 읽기 전용 툴은 허용하고, 셸·네트워크·쓰기는 차단하거나 승인을 받는다. 그룹별 조절은 M9.
- **정책은 공통 기준선 + 팀별 강화**: 공통 정책이 모든 장비의 최소 기준(baseline)이다. 팀(그룹) 정책은 그 위에서 **더 엄격하게만** 바꿀 수 있다
  (룰 추가·켜기, 응답 단계 상향 — 예: 데이터팀은 `destructive-sql`을 block, 허용 목록 축소). 완화는 팀 정책으로 할 수 없고,
  필요하면 보안팀이 공통 정책 자체를 고친다(M9). 그 전까지는 룰 파일의 응답 단계가 모두에게 적용된다.
- **승인은 사용자가, 감사는 보안팀이**: `require_approval`은 사용자 본인이 에이전트 화면에서 승인한다. 승인·거절 결과는 모두 기록되고,
  보안팀은 콘솔에서 "사용자가 승인한 위험 행동"을 사후 감사하다가 이상하면 원격 조치(세션 중단, 격리)를 한다(M7 감사 화면, M11 원격 대응).
- **줄어든 판정은 라벨로 남긴다**: 그렇게 처리된 이벤트에 `labels["sentinel.verdict"]`(예: `degraded`, `fallback`)를 붙여 기록한다. 스키마는 바꾸지 않는다.
- **전송 대기열 우선순위**: 이벤트에 등급(낮음·보통·높음·긴급)을 매긴다. 대기열이 차면 낮은 등급부터 버리고, 다시 연결되면 높은 등급부터 보낸다.
- **가상 직원 LLM**: 기본은 로컬 Ollama(외부 API 불필요)로 하고, 직원마다 모델 백엔드를 설정으로 바꿀 수 있게 한다.
  개발 머신은 Mac 16GB이므로 Ollama는 호스트에서 직접 실행하고(Docker 안에서는 Metal GPU를 못 쓴다), 7~8B급 모델 하나를 직원들이 공유한다.
  동시에 움직이는 직원은 2~3명으로 잡고, 나머지는 일과 스케줄로 순서를 나눈다.

## 마일스톤

| # | 마일스톤 | 완료 기준 | 상태 |
|---|---|---|---|
| M1 | 저장소 뼈대 + 공통 스키마 v1 | `AgentEvent`/`Finding` 모델, JSON Schema, 6개 센서 예시 이벤트, 테스트 | ✅ |
| M2 | 로컬 탐지 엔진 | SG `detect.py` 룰 타입 이전(regex/rate/loop/sequence/inventory diff), redaction, S1~S3 룰 통과 | ✅ |
| M3 | Control Plane API | FastAPI + SQLAlchemy(SQLite): 장비 등록(토큰), 이벤트·finding 수집, 정책 v0(`rules/` 묶음 + 해시) 조회, compose 뼈대, 위협 모델 초안(`docs/threat-model.md`) | ✅ |
| M4 | Sensor core | 어댑터 인터페이스, 정책 pull·캐시(중앙이 끊기면 마지막 정책 사용), 정책 서명(Ed25519) 검증, 전송 큐·재시도, 등록 CLI. 예시 이벤트 replay로 센서 → 중앙 엔드투엔드 | ✅ |
| M5 | 로컬 데몬 + OpenClaw 어댑터 | `sentinel-sensor run`(어댑터 실행, 주기적 정책 동기화·전송), SG ingest/respond 이전, 사후 abort 집행, 셸 명령은 exec 승인으로 사전 거절, SG 대비 변경점 문서(`docs/from-sg.md`) | ⏳ |
| M6 | Claude Code hook 어댑터 | hook → 로컬 소켓 → 데몬 판정, PreToolUse에서 deny(첫 사전 차단), `ask`로 사용자 승인 후 결과 기록, 데몬이 없으면 캐시로 상태 없는 룰만 판정, 캐시도 없으면 툴 위험도로 허용·차단 + 라벨 기록, 두 종류 에이전트 동시 관제 | |
| M7 | Console v1 | 장비/사용자 인벤토리, 위협 타임라인, finding 상세(룰 근거, 마스킹된 증거), 사용자 승인 감사 목록 | |
| M8 | MCP 프록시 + 악성 MCP 시나리오 | tool poisoning, 미허가 MCP 서버 차단 | |
| M9 | 정책 관리 | 공통 정책 + 팀별 정책 계층(룰 on/off, 응답 단계·허용 목록 덮어쓰기), 정책 버전, 콘솔 편집기, 센서 pull 반영, 변경 감사 로그 | |
| M10 | 가상 직원 (LangGraph + Ollama) | 페르소나·일과 기반 LLM 직원 다수, 녹화/재생 모드, `docker compose up`으로 전체 데모 | |
| M11 | 원격 대응 + 상관 분석 | 원격 abort/quarantine, 콘솔 승인 큐(에이전트 화면에서 승인을 못 받는 경우), 다중 사용자 캠페인 탐지 | |
| M12 | 멀티 호스트 | 다른 PC/VM에 센서 한 줄 설치 + 등록 토큰(LAN 또는 Tailscale), 등록 시 장비 인증서 발급(서버가 CSR 서명) + mTLS, 토큰·인증서 폐기 | |
| M13 | 평가 + 포트폴리오 마감 | 시나리오별 탐지율·오탐률 표, 위협 모델 완성, 데모 영상, README·설계 문서 정리 | |
